# Roadmap

The categorical hygiene baseline is implemented: a normative aggregate model,
exact package classification, category-aligned workspace, and separate
authority-free local transport/application composition. Final artifact
requalification remains part of the current release-readiness work.

1. Extend the implemented deterministic models, canonical wire/recovery mutation,
   coverage-guided fuzzing, filesystem interruption, and commit-pinned local
   release qualification with broader command models plus repeated remote and
   supported-host campaigns.
2. Extend the implemented stable-topic, rename, reversible-resolution,
   bounded depth-one supersession, and bounded display-alias substrate only
   through separately decided move/copy, deletion, and conversation-collection
   laws.
3. Extend the qualified local exact-record offline backup/restore mechanism with
   real device/power-loss campaigns, authenticated/encrypted transport,
   retention and rollback policy, then qualify upgrade/rollback and an
   additional physical store only when a deployment profile requires broader
   claims.
4. Extend the implemented exact key/scope/revision operator authority and Aegis
   decision-correlation evidence only with a separately defined coordinated
   recovery protocol; the current mechanism is explicitly non-atomic.
5. Extend the release-qualified bounded immutable attachment-reference profile
   only through separately authorized resolver or external-lifecycle adapters;
   do not import blob bytes, bearer locators, scanning, download authority, or
   external retention into Agora.
6. Extend the release-qualified typed Vellum artifact-reference profile only
   through separately authorized resolver or promotion adapters. The separately
   owned identity adapter proves exact conversion against Vellum's public
   workspace/document/source-revision types; document content, live witnesses,
   editing, persistence, agent behavior, and cross-engine transaction claims
   remain outside Agora.
7. Complete the adopted R102 Chronos scheduled-publication composition after
   the implemented Agora trusted-port and deployed private-local client slices:
   Chronos owns scheduled objects, clock, cancellation, and temporal execution;
   Agora admits only an authenticated, idempotent publication attempt with
   explicit schedule-origin identity. Close cancellation races, late execution,
   unavailable Agora, and unknown-result recovery without importing tasks or
   scheduling into Agora. The separate adapter receipt-gates its canonical
   intent/allocation/reconciliation journal and exposes every cancellation cut;
   remaining work is live Chronos admission, Workbench attachment, and
   integrated release/soak qualification rather than another Agora transport.
8. Implement the adopted R103 Hermes notification-delivery composition through
   a separate adapter: content-minimized observer-bound projection, durable
   exact handoff, current visibility and revocation, endpoint uncertainty, and
   consumer acknowledgment that never mutates Agora read state.
9. Complete the application/presentation split. `agora-tui` remains a reusable
   Ratatui component over the public client, with no argument parsing, terminal
   lifecycle, daemon startup, or process-exit policy. An Agora-owned standalone
   CLI must be able to select an embedded or remote service and run either that
   TUI or a bounded headless command. Workbench must reuse the same TUI and
   client contracts while optionally hosting Agora's service runtime under its
   own single-process lifecycle; it must not merge Agora authority or state with
   peer engines. Qualify standalone interactive, standalone headless, Workbench
   interactive, and Workbench headless journeys against the same protocol laws.
   The single-principal private-endpoint authenticator and non-regressing system
   clock and bounded fresh-engine bootstrap are now Agora-owned production
   inputs; public Aegis Unix session/grant selection, durable create/open recovery, and the
   standalone process shell remain before the production owner factory closes.

Agent harness selection, prompting, retries, and execution remain out of scope.
